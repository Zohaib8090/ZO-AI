## 1. What ZO-AI is now

* **Desktop app** (GTK4/libadwaita, `crates/zo-ai`): chat agent with computer tools, projects, artifacts, scheduler, memory agent
  (vector-ish memory), personalities, tray icon + Activity page, model pinning UI, sign-in + sync, desktop link, terminal dock.
* **Cloud server** (`crates/zo-server`, tiny_http, deployed on Render free plan, Firebase project `zo-ai-144`, Firestore eur3):
  PUBLIC multi-user service. Every person signs in with Google or e-mail+password. Per-person tenants and Firestore areas.
  Bring-your-own API key (stored encrypted per tenant). Non-admins ("restricted") get only web search, page reading and memory
  tools on the server; admins (env `ZO_ADMIN_EMAILS`) get everything on the SERVER container. Serves the **web app**
  (`crates/zo-server/web/index.html`, one file, desktop-identical look, voice, attachments, notifications/PWA, Run on My computer).
* **Desktop link** (docs/LINK.md): the web/phone can run turns on the person's own desktop (off by default, approvals on the desktop).
* **Claude Code**: each person logs in on their own computer; the web reaches it through the link. Admin-only server-hosted Claude token exists.
  Per-person server-hosted tokens (operator switch `ZO_CLAUDE_CODE_USERS=admins|all`) were designed but NOT built (see section 6).
* **Terminal client** `zo` (`crates/zo-cli`), **phone daemon** (`~/Documents/zohara-link`, separate repo, alpha channel), **MCP server** `zo-mcp`.
* **Native Android app** (Kotlin/Compose, `apps/android-native`) being built; legacy Capacitor wrapper in `apps/android-web`.
